# Maintaining project records

Follow the map to the relevant requirement, task or team tracker. Update the existing entry when a confirmed change affects later behavior, acceptance, ownership or the next action. Keep the rationale for significant decisions where future maintainers will find it. Preserve the project's identifiers and link superseded decisions to their replacements.

A small project can keep its few durable facts in the map until they need their own source. Parallel contributors coordinate writes to a shared task list before allocating identifiers.

When sources conflict, compare their purpose, environment, revision, date and evidence. Implementation documents observed behavior. The agreed requirement guides acceptance. For a delivered result, distinguish what was implemented, verified, accepted, merged and deployed. Only update records within the requested scope. See [acceptance evidence](acceptance.md) for an incomplete or disputed result and [handoffs](coordination.md) when someone else must continue.
